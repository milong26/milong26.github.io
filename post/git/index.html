设计理念#

正在看一个git相关的talk，我发现现在技术更新这么快，学习怎么使用git肯定是不够的？还是不行的？

我更应该去了解更底层的，也就是它的设计思路。

这样不管技术如何更新，我都应该能快速使用。

真正可迁移的能力来自两个层次：先掌握工具的使用方式解决问题，再理解它背后的设计思想、抽象模型和取舍。比如 Git 不只是记命令，而是理解它为什么采用“对象模型、快照、分支指针、分布式协作”等设计，这样即使未来出现新的版本控制工具，你也能快速迁移。技术会变，但优秀工具背后的思想（抽象、数据结构、系统设计、权衡）变化更慢。

Git 背后的核心思想，不是“保存代码变化”，而是“管理一个不断演化的历史状态”。它把项目看成一个由提交（commit）组成的有向图，每次提交记录一个项目快照，而不是简单记录一串修改步骤；分支（branch）本质上只是指向某个提交的轻量级指针，所以创建分支成本极低。

更深层的设计理念有几个：

  1. 去中心化（Distributed）
    Git 假设每个开发者都拥有完整的项目历史，而不是依赖一个中央服务器。因此开发可以离线进行，协作通过合并不同历史分支完成。

  2. 不可变历史（Immutable History）
    Git 倾向于“不修改过去，而是在过去基础上产生新的状态”。提交一旦产生，就像历史节点一样存在，通过新的提交表达变化。这种设计让回滚、审计、追踪原因变得可靠。

  3. 数据对象化（Object Model）
    Git 把文件、目录、提交都抽象成对象，并通过哈希标识它们。也就是说，Git 管理的不是“文件夹”，而是一组相互引用的数据对象。这让内容寻址、去重、完整性校验成为可能。

  4. 鼓励并行探索（Branching as a First-Class Concept）
    传统系统把分支看成特殊操作，而 Git 认为“创造不同方向、实验、再合并”是软件开发的正常流程。因此分支被设计得非常廉价。

所以学习 Git 真正应该理解的是：它把软件开发从“修改一个文件”提升成“管理一个状态空间中的演化过程”。 一旦理解这个思想，你不仅会 Git，也更容易理解数据库版本控制、配置管理、协作系统，甚至 AI 模型版本管理等类似工具。

使用#

上传#

  1. 进入文件夹folder_to_upload，git bash（命令行也行，能登陆到github账号就行）
  2. 初始化
git init
  1. 添加
git add .
  1. 提交
git commit -m "随便写什么"
  1. github上新建一个仓库，不要勾选Initialize this repository with a README file（创建之后能看到它的教程的）
  2. 将本地仓库与 GitHub 仓库关联
git remote add origin https://github.com/用户名/仓库名.git
  1. 修改分支
git branch -M main
  1. 上传
git push -u origin main

可以搞成sh形式

#!/bin/bash

# 检查是否提供 commit 信息
if [ -z "$1" ]; then
  # 如果没有提供 commit 信息，使用默认值
  commit_message="Auto commit: $(date '+%Y-%m-%d %H:%M:%S')"
  echo "No commit message provided. Using default: \"$commit_message\""
else
  # 使用用户提供的 commit 信息
  commit_message="$1"
fi

# 自动添加、提交并推送
git add .
git commit -m "$commit_message"
git push

# 提示完成
echo "Changes have been added, committed with message \"$commit_message\", and pushed successfully!"

git add . 的范围是当前目录及其子目录

git push 会向上找.git文件，所以与执行的目录无关（除了多重文件夹有不同的git配置）

提交合并#

面对：

This branch is 113 commits ahead of, 23 commits behind xxx/xxx:branch

怎么处理，两种方式，rebase和just merge。

rebase#

提交历史会清晰，但是工作量比较大。

rebase 的过程是：Git 会把你本地分支的 113 次提交，一个个“摘出来”，然后“重新应用”在 huggingface/lerobot 的最新 23 个提交之后。

just merge#

直接合并的话提交历史很混乱。

git fetch upstream
git merge upstream/main

本地仓库关联github#

在 GitHub 上创建自己的仓库

  • 登录 GitHub，点击 New Repository

  • 取一个名字，例如 lerobot-my-version

  • 不要勾选 “Initialize with README”，保持空仓库

假设你的仓库地址是：

https://github.com/你的用户名/lerobot-my-version.git

将你的本地仓库关联到自己的远程仓库

git remote rename origin upstream
git remote add origin https://github.com/你的用户名/lerobot-my-version.git

  • upstream → 原作者仓库

  • origin → 你自己的仓库

什么原因：Git push 到远端时，连接被远端或中间网络断开了，不是代码提交本身有问题。

怎么解决：先检测

ssh -T git@github.com

看到：

git config --global http.proxy http://127.0.0.1:7890

然后设置https：

以后如果要取消：

git config --global --unset http.proxy
git config --global --unset https.proxy

OpenSSL#

尝试git push的时候遇到报错：

git push
OpenSSL version mismatch. Built against 30000020, you have 30600040
fatal: 无法读取远程仓库。

请确认您有正确的访问权限并且仓库存在。

怎么处理？

这个错误是因为 Git 编译时使用的 OpenSSL 版本与系统当前安装的 OpenSSL 版本不匹配。这通常发生在你升级了系统的 OpenSSL 库之后。
